# HANDOFF.AI — EMS to Hospital Handoff

Transforms paramedic radio reports into structured hospital handoff data using AI.

**The flow:** Ambulance (paramedic) → HANDOFF.AI → Hospital ER

### <ins>How It Works</ins>

1. Paramedic provides a radio report — live mic, pasted text, or a built-in sample case.
2. **faster-whisper** (local, runs on your machine) transcribes speech to text. During live recording it transcribes short chunks to listen for the stop phrase; once you stop, it re-transcribes the *complete* recording for accuracy.
3. A **transcript corrector** repairs obvious ASR errors in medical vocabulary (mainly drug names) and flags ambiguous mis-hearings for the LLM to resolve from context.
4. A **lexicon retrieval (RAG)** step pulls the EMS terms actually present in the report and injects them — plus the flagged suspects — into the extraction prompt.
5. An **LLM** (Groq / Ollama / OpenRouter — your choice) extracts structured data: vitals, history, interventions, allergies, code status, hospital prep actions, etc.
6. *(Optional)* If a **textbook vector store** has been built (see *Textbook-Grounded Guidance* below), a second retrieval step pulls relevant passages from embedded EMS references and the LLM suggests **grounded, cited courses of action** for the receiving team. Skipped automatically when no store is present.
7. The hospital receives an actionable prep report *before the patient arrives*.

> **Note on providers:** the Groq / Ollama / OpenRouter choice **only** affects the extraction LLM (step 5). Recording and transcription always run locally via `faster-whisper` regardless of which provider you pick.

# 1. Dependencies

Run the following command in the terminal to create a Python virtual environment and generate folder `.venv`:

```bash
$ python3 -m venv .venv
```

Run the following command in the terminal to use the created Python virtual environment:

```bash
$ source .venv/bin/activate
```

Run the following command in the terminal to install Python packages in the created Python virtual environment:

```bash
$ pip install -r requirements.txt
```

Run the following command in the terminal to install PortAudio (required by `sounddevice`) in the created Python virtual environment:

```bash
# macOS
$ brew install portaudio

# Ubuntu / Debian
$ sudo apt install portaudio19-dev

# Windows — usually bundled automatically
```

### <ins>Optional extras (recommended for the transcript corrector)</ins>

The transcript corrector degrades gracefully without these, but installs the full correction path when present:

```bash
$ pip install jellyfish pyspellchecker
```

- **`pyspellchecker`** gates fuzzy auto-correction. Without it, the corrector cannot prove a token isn't ordinary English, so fuzzy drug-name correction is disabled entirely (deterministic known-misspelling fixes and context rules still run).
- **`jellyfish`** adds a phonetic tie-breaker to fuzzy matching. Losing it is harmless.

# 2. Provider Method

## 2.1 AI Choice

The provider you select drives **only** the extraction LLM. Transcription is always local.

### <ins>Groq (Recommended)</ins>

**Groq is the recommended provider.** It's free, cloud-hosted, fast, and requires no local setup.
The menu defaults to Groq and will prompt for your API key.

1. Get a free API key at [console.groq.com](https://console.groq.com)
2. Set it as an environment variable (see below)
3. Run the script and press Enter at the provider prompt (defaults to Groq)

### <ins>Other</ins>

| Provider | Extraction model | Notes |
|---|---|---|
| **Groq** ✅ (default) | `llama-3.3-70b-versatile` | Free tier, cloud, fast — recommended |
| **Ollama** | `qwen3:8b` | Local, fully offline, requires [install](https://ollama.ai/download) + `ollama pull qwen3:8b` |
| **OpenRouter** | `meta-llama/llama-3.2-3b-instruct:free` | Cloud, some free models available at [openrouter.ai](https://openrouter.ai) |

> Transcription (all providers, always local via `faster-whisper`, CPU `int8`): during live recording, Whisper **`small`** transcribes short trailing windows to catch the stop phrase quickly; once you stop, the *complete* recording is re-transcribed with **`large-v3-turbo`** for the accurate report. Switch `device="cpu"` to `device="cuda"` in `handoff.py` on an NVIDIA/Jetson machine for a large speedup.

## 2.2 API Key Setup

NEVER hardcode your API key, use an environment variable. Replace `gsk_your_key_here` with your API key in a `.env` file:

```bash
# macOS / Linux
export GROQ_API_KEY="gsk_your_key_here"

# Windows (Command Prompt)
set GROQ_API_KEY=gsk_your_key_here

# Windows (PowerShell)
$env:GROQ_API_KEY="gsk_your_key_here"
```

The script reads it automatically via `os.getenv("GROQ_API_KEY")` in other files.

## 3.3 Results

After selecting a Case (and typing or recording for **4** or **5** respectively), the transcript first passes through the corrector, then the extraction LLM. You should see output similar to the following.

```bash
# terminal output
[*] Corrected: <...> -> <...>              # any auto-applied ASR fixes
[?] Possible mis-hearing: <...>            # ambiguous terms left for the LLM

============================================================
CORRECTED REPORT (<N> fixes applied):      # or "EMS RADIO REPORT (INPUT):" if none
============================================================
<...>

[*] Processing EMS report...
    Using: <PROVIDER> — <model>
--------------------------------------------------

============================================================
[HOSPITAL] HOSPITAL ER DASHBOARD - INCOMING PATIENT
============================================================

<...>

============================================================

[SAVE] Full JSON: output/handoff_report.json
```

During live recording, a short trailing audio window is transcribed repeatedly (into a temp file such as `recording_check.wav` inside a temporary directory) purely to detect the **"confirm report ready"** stop phrase. The complete captured audio is saved to `output/final_recording.wav`, then re-transcribed and processed into a structured handoff report.

Results are printed as a color-coded ER dashboard in the terminal and saved to `output/handoff_report.json`. The JSON contains ~20 structured fields including alert type, priority level, vitals, EMS interventions, patient history, allergies, code status, and time-critical hospital prep actions. Any corrections the pipeline applied are recorded under `data_quality.assumptions` so the receiving ED can see what was inferred rather than heard.

# 4. Textbook-Grounded Guidance (Optional)

Step 6 of the pipeline — LLM-suggested **courses of action, grounded in and cited to real EMS references** — is optional and off until you build a vector store. If no store exists, the pipeline simply skips this step; nothing else changes.

To enable it:

1. Pull the embedding model (one-time). Embeddings run locally via Ollama regardless of which extraction provider you use:

    ```bash
    $ ollama pull nomic-embed-text
    ```

2. Drop your source PDFs into the `dataset/` folder at the project root (it ships empty, with just a .gitkeep placeholder).

3. Build (or incrementally update) the store, written to `database/`:

    ```bash
    $ python -m src.embed_documents
    ```

    Re-running embeds only PDFs that aren't already in the store. Use `--rebuild` to wipe and re-embed everything, or `--help` to see all flags (`--pdf-dir`, `--out-dir`, `--chunk-size`, `--overlap`, etc.).

At runtime, `HandoffAI` looks for the store in `database/` (relative to the project root) and, when present, retrieves the most relevant passages for each handoff and asks the LLM to base its recommendations only on those excerpts — printed as **suggested courses of action** and included in `output/handoff_report.json` under `clinical_guidance`.

> This is decision support only, grounded in the provided textbook excerpts — not a directive. Clinical judgment is always required.
